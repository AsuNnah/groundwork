# P8: Verify in sandbox

Test where the app will really run.

1. Per target, run its tests at the best local tier, then at the release tier (`gw doctor` Targets, `docs/test-strategy.md`): `gw run <target> <S0|S1|S2|S3> -- <test command>` writes a receipt.
   - `gw task done` receipts are S0. A project with no targets (a library or script) needs nothing more.
   - **S1:** the pack's container command (the Playwright image for web; docker compose with a real DB for backend). **S2:** an emulator or VM (needs virtualization, H0). **S3:** CI from the pack's S3 recipe: push a branch, then `gw run <target> S3 -- gh run watch <id> --exit-status`.
   - A receipt claims only the isolation its command shows. A script that starts the environment itself: `gw run <target> S1 --wrapper -- <script>`.
2. **Quality sensors (standard+)**, each recorded with `gw run <target> S0 -- <cmd>`: `semgrep scan --config auto --error`, `npx --yes jscpd@5.4.2 --threshold 5 src`, and the stack's mutation test from `gw maintain` for logic-heavy modules. Install only with approval; a missing one is a warning, not a stop.
3. **User acceptance (standard+ new products):** a plain-language checklist from the FSD acceptance criteria (screenshots for UI), with results in `docs/uat.md` (`templates/uat.md`). A change lists its acceptance steps in `proposal.md`.
4. A failure goes back to P7 as a new task. A target without a passing release-tier run needs a waiver the user approved, in `state.json` `waivers`: `{"target":"ios","reason":"…"}`.
5. `gw phase P8 done`.
