# P8: Verify in sandbox

Test where the app will really run.

1. For each target, run its tests at the best tier this host supports, then at the release tier (see `gw doctor` Targets and `docs/test-strategy.md`):
   `gw run <target> <S0|S1|S2|S3> -- <test command>`. This writes a receipt to `.groundwork/runs/`.
   - **S1:** the container command from the pack (e.g. the Playwright image for web; docker compose with a real DB for backend).
   - **S2:** an emulator or VM (Android emulator, Windows VM, iOS Simulator on a Mac). Needs working virtualization (see H0).
   - **S3:** CI. Create or update a workflow from the pack's S3 recipe, push a branch, read the result (`gh run watch` / `gh run view`), and record it: `gw run <target> S3 -- gh run watch <id> --exit-status`.
2. Store artifacts (logs, screenshots, junit, coverage) under `.groundwork/runs/<id>/`.
3. **User acceptance walkthrough** (standard+): turn the FSD acceptance criteria into a plain-language checklist with steps the user can try, plus screenshots for UI apps. Record the results in `docs/uat.md` (`templates/uat.md`).
4. A failure goes back to P7 as a new task. Don't mark P8 done while any target lacks a passing run at its release tier, unless a waiver with a reason is added to `.groundwork/state.json` `waivers` (`{"target":"ios","reason":"..."}`) and the user approved it.
5. `gw phase P8 done`.
