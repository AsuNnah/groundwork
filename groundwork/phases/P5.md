# P5: Design docs (only what the tier and targets need)

**Run `gw docs` first.** It lists exactly the documents this tier and these features need, and GATE 1 checks exactly that list. Write those, keep them short, and write no others unless the user asks. The table below says what goes in each.

| Doc | When | Template |
|---|---|---|
| FSD: features + acceptance criteria (linked `REQ-` IDs) | standard+ | `templates/fsd.md` |
| AFD: user/system flows (Mermaid) | flows with branches or several actors | `templates/afd.md` → `docs/afd.md` (or inline in the FSD) |
| TRD: architecture, modules, data, integrations | standard+ | `templates/trd.md` |
| BSD: API contracts (`docs/contracts/openapi.yaml`) + DB schema | has a backend or DB | `templates/bsd.md` → `docs/bsd.md` (small projects: the TRD section) |
| DBD: design brief (screens, states, tokens, accessibility) | has a UI | `templates/dbd.md` → `docs/dbd.md` |
| **Mockups: wireframe → visual → clickable prototype (Figma or HTML)** | has a UI, small tier and above | `phases/MOCKUP.md` → Figma file or `docs/mockups/`, approval in `docs/dbd.md` |
| SRD: threats, authn/z, data classes, platform/store policy | auth, personal data, payments or a public API; always at large | `templates/srd.md` |
| Platform notes: permissions, min OS, signing, store rules | per target | `templates/platform.md` → `docs/platform/<target>.md` |

Large projects: split the FSD into `docs/fsd/00-conventions.md` (shared components, dialogs, validation, roles, scenario IDs), one file per area in `docs/fsd/sections/`, and an index holding the PRD→FSD traceability table (see `templates/fsd.md`).

Rules:
- Link everything back to PRD IDs. Mark any guess `[NEEDS CLARIFICATION]`.
- Don't create docs nobody will read. A doc `gw docs` doesn't list is skipped by default; a listed one you think is pointless: say why and re-check the features (`gw set features=…`) instead of writing filler.
- A reference app is involved: base flows, API, data and UI on `docs/research/<ref>.md` (`phases/RESEARCH.md`), not on memory.
- Use installed design skills if they exist, e.g. `api-and-interface-design`, `database-schema-designer`, `security-requirement-extraction`, `diagram-design`.
