# P5: Design docs (only what the tier and targets need)

| Doc | When | Template |
|---|---|---|
| FSD: features + acceptance criteria (linked `REQ-` IDs) | standard+ | `templates/fsd.md` |
| AFD: user/system flows (Mermaid) | flows with branches or several actors | `templates/afd.md` → `docs/afd.md` (or inline in the FSD) |
| TRD: architecture, modules, data, integrations | standard+ | `templates/trd.md` |
| BSD: API contracts (`docs/contracts/openapi.yaml`) + DB schema | has a backend or DB | `templates/bsd.md` → `docs/bsd.md` (small projects: the TRD section) |
| DBD: design brief (screens, states, tokens, accessibility) | has a UI | `templates/dbd.md` → `docs/dbd.md` |
| SRD: threats, authn/z, data classes, platform/store policy | always for standard+ | `templates/srd.md` |
| Platform notes: permissions, min OS, signing, store rules | per target | `templates/platform.md` → `docs/platform/<target>.md` |

Rules:
- Link everything back to PRD IDs. Mark any guess `[NEEDS CLARIFICATION]`.
- Don't create docs nobody will read. For each skipped doc, record why in `gw phase P5 done "skipped DBD: no UI"`.
- Use installed design skills if they exist, e.g. `api-and-interface-design`, `database-schema-designer`, `security-requirement-extraction`, `diagram-design`.
