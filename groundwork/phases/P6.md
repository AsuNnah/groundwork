# P6: Plan → GATE 1

1. `docs/plan.md` (from `templates/plan.md`): milestones, risks, and a **Complexity Tracking** section.
2. `.groundwork/tasks.json`: an ordered task list. Each task:
   `{"id":"T01","title":"...","req":["REQ-001"],"files":["src/..."],"depends_on":[],"parallel":false,"test_first":true,"verify":"<command>","tier":"S1","status":"todo"}`
   Size tasks at 15–60 minutes of agent work, with exact files and a verify command that runs on THIS host's dev method.
3. `docs/test-strategy.md`, per target:
   - which tests run at which sandbox tier (S0/S1/S2/S3), using the pack's `sandbox` and `test_tooling`;
   - the coverage bar (or a `CONSTRAINTS.md` via the `constraint-driven-development` skill);
   - the CI matrix for S3 targets.
4. **Pre-build checks.** Each one passes, or is justified in Complexity Tracking:
   - **Mockup approved** (targets with a UI): the user approved the mockup in `docs/dbd.md` (`phases/MOCKUP.md`), and the tasks build those screens.
   - **Simplicity:** the fewest projects, services, and dependencies that meet the PRD.
   - **No speculative abstraction:** nothing "for later".
   - **Integration-first:** real DB and services in tests where practical (S1).
   - **Target reality:** every target has a verify path at its release tier.
   - **Security:** SRD items are mapped to tasks.
5. `gw gate G1`. Fix everything it lists.
6. Show the user a short plan summary: milestones, targets with their test tiers, risks, and open waivers. Ask for approval.
7. On approval: `gw gate G1 --approve "<the user's exact words>"`, then `gw phase P6 done`.

Until G1 is approved, the pre-edit hook blocks source edits in standard/large projects. Docs, tests, and `.groundwork/` stay editable.
