# P10: Release → GATE 2

1. Follow each target pack's `release` list: versioning, changelog, signing, packaging, and the store/hosting checklist.
2. **Secrets** (keystores, certificates, tokens) never go into the repo or docs: use CI secrets or a secret manager, referenced by name.
3. Build the release artifacts on the tier the pack requires (e.g. iOS on a macOS runner) and record them with `gw run`.
4. Rollback readiness (`phases/OPERATE.md` D): the previous artifact is redeployable, migrations are expand/contract, mobile/desktop releases use a staged rollout. Run the routine security scan (`phases/SECURITY.md` A). First release: set up observability (`phases/OPERATE.md` A) and write `docs/runbook.md`.
5. `gw gate G2`; fix what it lists. A waiver needs a reason the user approved: `{"req":"REQ-004","reason":"…"}` or `{"target":"ios","reason":"…"}` in `state.json` `waivers`.
6. Show the user what will be released, where, the version, known issues, the third-party code used (`docs/credits.md`), and the rollback plan. Ask for approval.
7. On approval: `gw gate G2 --approve "<the user's exact words>"`. Publish only what was approved: publishing is outward-facing and hard to undo. Then `gw phase P10 done`.
