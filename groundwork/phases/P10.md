# P10: Release → GATE 2

1. Follow each target pack's `release` list: versioning, changelog, signing, packaging, and the store/hosting checklist.
2. **Secrets** (keystores, certificates, tokens) never go into the repo or docs. Use CI secrets or a secret manager. Reference them by name only.
3. Build the release artifacts on the tier the pack requires (e.g. iOS on a macOS runner) and record them with `gw run`.
4. `gw gate G2`. It needs G1, plus a passing run at the release tier for every target (or an approved waiver).
5. Show the user: what will be released, where, the version, known issues, and the rollback plan. Ask for approval.
6. On approval: `gw gate G2 --approve "<the user's exact words>"`. Publish only what was approved; publishing is outward-facing and hard to undo. Then `gw phase P10 done`.
