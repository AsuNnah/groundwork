# P9: Review

1. Code review of the whole diff since the baseline: correctness, simplicity, tests, and naming. Use the `code-review-and-quality` skill or a fresh-context reviewer subagent if available.
2. Security review when the change touches auth, input handling, DB, file system, network, crypto, secrets, or payments. Use `security-audit` / `security-and-hardening` if installed, and check every SRD item.
3. Platform review against `docs/platform/<target>.md`: permissions, store policies, accessibility, min OS.
4. Findings:
   - CRITICAL/HIGH must be fixed (back to P7), or waived with a written reason and user approval;
   - record MEDIUM/LOW in `docs/plan.md#follow-ups`.
5. `gw phase P9 done`.
