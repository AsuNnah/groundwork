# P9: Review

1. **Code review** of the diff since the baseline: correctness, simplicity, tests, naming. At standard+ the reviewer is not you: a subagent with read-only tools (Read, Grep, Glob) given only the diff, the PRD/FSD sections, the tasks and the reviewer's brief (`gw team --json`), not this chat, using `code-review-and-quality` if installed. It returns real problems by severity (correctness, security, data loss, missing tests, unmet requirements), not style. Or a human, or a new session. Log the hand-off: `gw team log reviewer <tokens>`. Large tier: one writer per file; reviewers don't edit.
2. **Security review** when the change touches auth, input handling, DB, files, network, crypto, secrets or payments (`security-audit` / `security-and-hardening`; check every SRD item). **Platform review** against `docs/platform/<target>.md`.
3. Record each finding: `gw review add <CRITICAL|HIGH|MEDIUM|LOW> "<finding>" --verdict <fixed|waived|deferred|open> [--reason "…"]`. CRITICAL/HIGH: fix it (a new P7 task) or waive it with a reason the user approved. MEDIUM/LOW also go into the follow-ups (`docs/plan.md`, or the change's `proposal.md`). Then `gw review done --reviewer <fresh-context|human|ci> "<summary>"`.
4. **Converge check:** compare what was built with the intent, PRD and mockup. Drift goes to the user, who picks: the docs change, or new tasks fix the code. Never rewrite finished tasks.
5. `gw phase P9 done`.
