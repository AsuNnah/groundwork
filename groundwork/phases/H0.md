# H0: Host scan (always first)

Goal: know the machine before planning anything. The scan decides which tools to install, the dev method, and where each target can be built and tested.

## Steps
1. Run `gw doctor` (it scans automatically on first run, when the host changed, or when the last scan is older than 7 days; `--fresh` forces a scan).
   - Linux/macOS/WSL uses `groundwork/scan/scan.sh` (POSIX sh, no dependencies).
   - Windows uses `groundwork/scan/scan.ps1` (built-in PowerShell). If Node is missing, run the scanner directly: `sh groundwork/scan/scan.sh` or `powershell -ExecutionPolicy Bypass -File groundwork\scan\scan.ps1`. Then put Node first in the install plan.
2. Read the report and summarise it for the user in 4–8 lines:
   - the machine (laptop/desktop/VM/container/WSL, OS, arch, RAM, disk, GPU);
   - the **dev method** and why;
   - which targets can be developed and tested here, and which need CI/remote (S3);
   - every non-ok check as a notification: what was found → the exact fix → the impact until it's fixed.
3. Treat these the same way as a missing program, and offer the fix:
   - **Virtualization capable but not configured:** VT-x/AMD-V disabled in BIOS, KVM module not loaded, user not in the `kvm` group, no nested virtualization in a VM or WSL, Hyper-V off.
   - **Container engine installed but unusable:** no socket permission, daemon stopped.
   - **Outdated tool versions.**
4. Do not install anything in H0. Installs happen in P3 after targets are known.
5. `gw phase H0 done`.

## Dev methods (chosen by `gw`; the user may override; record overrides in `docs/adr/`)
| id | When | How to work |
|---|---|---|
| devcontainer | Linux with a usable container engine | toolchains in containers per project, mise for host tools |
| native-user-scope | no containers and/or no admin | mise / uv / SDKs in the user's home, no sudo |
| wsl2-first | Windows with WSL2 | web/backend/cli/android-build in WSL2; .NET/WinUI + Windows UI tests native |
| native-winget | Windows admin without WSL2 | winget installs |
| native-macos | macOS | brew + mise; required for iOS/macOS |
| light | < 8 GB RAM, < 4 threads, or < 20 GB free | no local emulators/VMs; heavy builds and tests on CI |
| in-place | agent already inside a container | project-local tools only; emulators/VMs on CI |

## Sandbox tiers
S0 host · S1 container · S2 emulator/VM (needs virtualization) · S3 CI / remote runner / device farm / real hardware.
