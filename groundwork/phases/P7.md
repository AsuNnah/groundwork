# P7: Build

One task at a time: the next `todo` task whose `depends_on` are done.
1. First task of a feature: create a branch (or worktree) and run the baseline tests (`phases/CHANGE.md` step 1).
2. `gw task start T01` before writing its code. The previous task's work is already committed (step 6), so its diff budget and review see only this task.
3. **Test first** when `test_first`: write the failing test (it names the REQ ID) and see it fail.
4. Before writing a non-trivial part from scratch, look for proven open-source code to reuse (`phases/REUSE.md`). Make the smallest change that passes, in the codebase's own patterns. No unrequested features.
5. `gw task done T01` runs the check and records a receipt; on a failure it says what to do next. Fix the root cause (`debugging-and-error-recovery`); never weaken tests, linters or configs.
6. Commit atomically: `type(scope): summary (T01, REQ-001)`.

- UI tasks build from the approved mockup (`phases/MOCKUP.md` §5). A change to the look goes through the mockup first.
- **Large tier, parallel workers:** `gw team` lists the waves of `parallel` tasks whose dependencies are done and whose `files` don't overlap, at most 3 at a time. Each worker is a subagent with its own git worktree and branch, given the task JSON, the doc sections and its role's brief (not this chat). It commits there after the task's check passes and doesn't run `gw`. You integrate one task at a time: `gw task start`, merge its branch, `gw task done`. A cheaper model is fine for small, well-specified tasks. Every other task you build yourself, in order. After each worker: `gw team log <role> <tokens>`.
- Scope changes: update the PRD/plan first and rerun only the affected phases (new target or stack: P2+P3; new dependency: P4).
- All tasks done: `gw phase P7 done`.
