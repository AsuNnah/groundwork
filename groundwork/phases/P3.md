# P3: Environment readiness

1. `gw doctor` checks tools for the chosen targets and stacks, on top of the H0 host checks.
2. `gw plan-install` prints the install/fix commands that suit this host. It picks mise first, then the OS package manager (winget/brew/apt/dnf/pacman), then the official installer.
3. Present the plan grouped as: **blocking** (must install), **recommended** (affects sandbox tiers), **optional**. For each item show the command, scope (user/project/system), whether it needs admin, and why it's needed.
4. Run only the lines the user approves. Show admin/sudo commands for the user to run themselves (`! <command>` in Claude Code), unless they explicitly ask you to run them.
5. After each install, rerun `gw doctor` until no **block** item remains. Warn items may stay open; each is a recorded notification with its fallback.
6. Pin versions so every machine and CI uses the same ones. Write `.mise.toml` / `.tool-versions` / `.nvmrc` / `global.json` / Gradle wrapper, whichever the stack uses. When the dev method is `devcontainer`, run `gw devcontainer`: it writes `.devcontainer/devcontainer.json` for every target stack (host-only stacks such as iOS are listed, not containerised) and prints the checks to run inside it.
7. `gw phase P3 done`. The doctor marks P3 `blocked` while any block check fails.

npm 12+ and pnpm 10+ don't run dependencies' install scripts until the project approves them. A package that needs one (Electron's binary, native modules) installs silently broken. When the install output lists blocked scripts, ask the user which to approve (`npm install-scripts approve <pkg>`, `pnpm approve-builds`) and commit the result.

Misconfiguration is handled exactly like a missing tool: report → fix → re-check. Examples are KVM disabled in BIOS, no permission on docker.sock, a JDK that is too old, or no nested virtualization.
