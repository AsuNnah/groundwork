# P0: Intake & sizing

1. Read the request, the repo (`README`, `CLAUDE.md`, `AGENTS.md`, `docs/`, build files) and `.groundwork/env-report.json`.
2. Pick the **stage**: `idea | greenfield | feature | bugfix | migration | upgrade | refactor | incident | security`. Existing codebases use a playbook alongside the phases:
   | Stage | Playbook |
   |---|---|
   | feature, bugfix, migration | `phases/CHANGE.md` |
   | upgrade (dependencies, SDKs, runtimes, store-policy deadlines) | `phases/UPGRADE.md` |
   | refactor / tech debt | `phases/MAINTAIN.md` |
   | incident, hotfix, rollback, monitoring setup | `phases/OPERATE.md`. **Mitigate first; skip P1–P6.** |
   | vulnerability / advisory / leaked secret | `phases/SECURITY.md`. P0/P1 findings follow OPERATE's hotfix flow. |
3. Pick the **size tier** by blast radius:
   | Tier | Typical scope | Phases |
   |---|---|---|
   | trivial | one-file fix, copy change, no behaviour risk | H0 P0 P7 P8 |
   | small | a few files, one feature, no new dependency or data change | + P1(light) P2(detect) P3 P6(light) P9 |
   | standard | new app or multi-file feature, a new dependency, any UI flow | all except P11 |
   | large | multi-module, multiple targets, data migration, team handoff | all |
   Raise to **standard or higher** for anything touching auth, payments, personal data, public APIs, data migrations, infrastructure, or release.
4. Ask only what changes the tier or the stage. State your assumptions.
5. `gw set stage=<stage> tier=<tier> name=<name>` then `gw phase P0 done`.
6. **Every new task gets P0, even a one-line fix.** For a trivial task it costs one command: `gw set stage=bugfix tier=trivial`. If you skip or work around any framework step, log it: `gw note workaround "…"`.

## Fitting an existing project (don't duplicate, map)
- **Docs live elsewhere** (another folder, a nested product repo, other file names):
  - point Groundwork at them, `gw set docs_dir=<path>` or per file `gw set docs.prd=<path> docs.plan=<path> docs.test_strategy=<path>`;
  - never create pointer or duplicate files to satisfy a gate;
  - file names match case-insensitively (`PRD.md`), and the GATE 1 edit guard allows edits there.
- **Its own ID scheme** (e.g. `A1..J6`): keep it. Add one line to the PRD header mapping it, e.g. `ID scheme: A1–J6 = REQ, S1–S7 = NFR, AF-xx = JRN`, and link to those IDs.
- **Phases done out of order or under another process:** record what exists with a note instead of redoing it, e.g. `gw phase P5 in_progress "FSD, AFD drafted before P2"`, and continue from the earliest phase still missing.
- **Several products in one folder** (workspace of repos): Groundwork tracks one project per `.groundwork/`. Copy `groundwork/` into each product folder you work in and start the agent there. Alternatively, keep one copy at the workspace root, set `docs_dir` to the active product, and set `name=`.
- **Project rule against the host's dev method** (e.g. no Docker in development): `gw set dev_method=native-user-scope dev_method_reason="no Docker in dev"`. Doctor and `gw run` then stop offering local container tiers (S1 goes to CI). `gw set dev_method=` clears it.
- **A reference app to model on** ("like X", "copy the closest existing bot"): `phases/RESEARCH.md`.
