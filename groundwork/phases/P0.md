# P0: Intake & sizing

1. Read the request, the repo (`README`, `CLAUDE.md`, `AGENTS.md`, `docs/`, build files) and `.groundwork/env-report.json`.
2. Pick the **stage**: `idea | greenfield | feature | bugfix | migration | upgrade | refactor | improve | incident | security`. Existing codebases use a playbook alongside the phases:
   | Stage | Playbook |
   |---|---|
   | feature, bugfix, migration | `phases/CHANGE.md` |
   | upgrade (dependencies, SDKs, runtimes, store-policy deadlines) | `phases/UPGRADE.md` |
   | refactor / tech debt | `phases/MAINTAIN.md` |
   | improve: an audit first, when no feature or bug is named ("improve my app", "what did we miss?") | `phases/IMPROVE.md` |
   | incident, hotfix, rollback, monitoring setup | `phases/OPERATE.md`. **Mitigate first; skip P1–P6.** |
   | vulnerability / advisory / leaked secret | `phases/SECURITY.md`. P0/P1 findings follow OPERATE's hotfix flow. |
3. Pick the **size tier** by blast radius:
   | Tier | Typical scope | Phases |
   |---|---|---|
   | trivial | one-file fix, copy change, no behaviour risk | H0 P0 P7 P8 |
   | small | a few files, one feature, no new dependency or data change | + P1(light) P2(detect) P3 P6(light) P9 |
   | standard | new app or multi-file feature, a new dependency, any UI flow | all except P11 |
   | large | multi-module, multiple targets, data migration, team handoff | all |
   Raise to **standard or higher** for anything touching auth, payments, personal data, public APIs, data migrations, infrastructure, or release.
4. Ask only what changes the tier or the stage. State your assumptions.
5. `gw set stage=<stage> tier=<tier> name=<name> features=<ui,api,db,auth,pii,payments,public: only those that apply>`, then `gw phase P0 done`. Features decide the documents (`gw docs`). Every new task gets P0, even a one-line fix (`gw set stage=bugfix tier=trivial`).
6. **Re-tier when the scope moves:** `gw set tier=<new> tier_reason="<what changed>"` (logged; `gw docs` shows the new list).
7. An existing project with its own docs folder, ID scheme or process, several products in one folder, or a no-Docker rule: `phases/FIT.md`.
