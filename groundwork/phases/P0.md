# P0: Intake & sizing

1. Read the request, the repo (`README`, `CLAUDE.md`, `AGENTS.md`, `docs/`, build files) and `.groundwork/env-report.json`.
2. Pick the **stage**: `idea | greenfield | feature | bugfix | migration | maintenance`. For an existing codebase with a change request, use `phases/CHANGE.md` alongside this one.
3. Pick the **size tier** by blast radius:
   | Tier | Typical scope | Phases |
   |---|---|---|
   | trivial | one-file fix, copy change, no behaviour risk | H0 P0 P7 P8 |
   | small | a few files, one feature, no new dependency or data change | + P1(light) P2(detect) P3 P6(light) P9 |
   | standard | new app or multi-file feature, a new dependency, any UI flow | all except P11 |
   | large | multi-module, multiple targets, data migration, team handoff | all |
   Raise to **standard or higher** for anything touching auth, payments, personal data, public APIs, data migrations, infrastructure, or release.
4. Ask only what changes the tier or the stage. State your assumptions.
5. `gw set stage=<stage> tier=<tier> name=<name>` then `gw phase P0 done`.
