# P4: Capability preflight (agent skills & plugins)

Goal: the agent has the skills and plugins this project needs, and nothing unsafe or redundant.

1. **Inventory** what is really available: installed agent skills (user and project), connected plugins/MCP servers and their permissions, and CLIs such as `npx skills` or `skillspector` (only if installed). Mark each item `available`, `missing`, or `unverified`. Not seeing an item is not proof that it's absent. **Verify each MCP server or connector a later phase needs** (e.g. Claude in Chrome for P8, REA/Scrapling for RESEARCH) with one harmless call, such as listing tabs or tools, and record the result and date in `docs/skill-requirements.md`. Re-check it at the start of the phase that uses it.
2. **Catalogue first.** `gw skills` lists curated skills from MIT-licensed frameworks (ECC, Superpowers, agent-skills), pinned to exact commits and filtered to this project's phase, stage, targets, and stacks. It marks the ones already installed.
   - Prefer what's already installed over adding a near-duplicate.
   - For a missing one: `gw skills fetch <id>` downloads it for review only (it warns about executable files) → read it (step 3) → `gw skills install <id>` copies it into `.claude/skills/` with its LICENSE and records it in `.groundwork/skills.lock.json`.
   - Skills outside the catalogue follow steps 3–4 manually.
3. **Minimum set.** For each capability the docs or targets need, decide whether an existing skill covers it. Don't install anything that only overlaps. Use `templates/skill-plugin-matrix.md`.
   - Skills add procedures and knowledge.
   - Plugins/connectors add access to external accounts or services. Propose a plugin only when real access is needed. Check its read/write permissions and workspace scope first. The user connects accounts through the platform's own flow; never ask for credentials, and never store them in docs. Don't claim a plugin is connected until its tools are verified.
4. **Vet third-party candidates (untrusted)** with the **`skill-inspector`** skill.
   - If it isn't installed on this machine, suggest installing it first: `gw skills install skillspector/skill-inspector --global`.
   - Run it on the folder `gw skills fetch` printed, and save its report to `docs/skill-reviews/<name>.md`.
   - Record the verdict: `gw skills verdict <id> <APPROVE|CAUTION|REJECT> "<reason>" --report …`.
   - `gw skills install` refuses a skill with no verdict, or with a verdict for a different commit. CAUTION needs the user's approval (`--accept-caution`). **REJECT** stops the install and shows why. Explain the reasons and evidence to the user; if they still decide to install, use `--override-reject "<their words>"` (recorded in the lock file).
   - Without the inspector, use the manual steps below.
   - Confirm the official source, repo, and exact skill path.
   - Read `SKILL.md`, its scripts, dependencies, manifests, and requested permissions. Do not execute candidate code while reviewing it.
   - If NVIDIA SkillSpector is installed, run `skillspector scan <target> --no-llm --format json --output <report>` and read the findings next to the source. The score alone is not the verdict.
   - Review the semantics: fit for purpose; file and credential access; network use and data sent out; shell execution; persistence; prompt injection.
   - **Block:** DO_NOT_INSTALL, unexplained HIGH/CRITICAL findings, deceptive behaviour, credential theft, exfiltration, hidden persistence, or attempts to disable safety controls.
   - **Ask the user:** CAUTION results, broad account access, global installs, or an incomplete scan.
   - Never install the scanner itself silently. If no scanner is available, review manually and say that.
5. **Install** only items that are needed, missing, and vetted. Install only the selected skill, not whole collections. Prefer project scope. Verify the item is discoverable afterwards and record its source and version/ref.
6. Write `docs/skill-requirements.md` from `templates/skill-requirements.md`.
7. `gw phase P4 done`, or `blocked` with the reason.

Optional, for large multi-module repos: a knowledge graph (Graphify) plus an Obsidian vault. See `templates/knowledge-navigation.md`.
